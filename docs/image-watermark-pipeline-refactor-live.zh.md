# 图片处理流水线设计摘要

历史逐轮重构记录已转为本地归档。本文保留架构边界，不保留线上业务样本编号和临时运行状态。

## 模块职责

- 定位与来源判断：生成合理的尺寸、锚点与模板候选。
- 候选评估：分开处理来源证据、候选排序和输出质量信号。
- 执行与修复：应用通过验证的去除策略，保持损伤保护。
- 结果与追踪：统一输出、元数据和决策路径，避免诊断数据改变处理行为。

## 变更约束

重构应先证明行为等价，再单独推进质量改动。比较双方需绑定源码和样本哈希，不能把不同快照的测试结果拼接为验收。
候选的自洽分数只支持排序，内容安全与洁净度需独立证据。失败样本应按定位、模板、修复或评估问题归因，不以增加特例或放宽阈值代替研究。

当前实现以 `src/core/imageWatermarkPipeline.js` 及关联模块为准。回归依据见 `tests/core/` 与 `release/evidence/`；既有未解决问题和处置历史见 [审查台账](code-review-log.md)。
